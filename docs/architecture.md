# World Interactive Agency architecture

WIA owns task definitions and selection, native scene authoring, public/private projection, evaluator rules, immutable episode policy, trial configuration and aggregation. The pinned `ESI` submodule contains upstream ESI-Bench source code and datasets. Separately licensed native simulator assets are external prerequisites and are not included in that submodule. ShowHarness supplies prompt assembly, model sessions, tool mediation, history, control leasing, traces and the physical execution loop.

The dependency direction is deliberate: base WIA imports only its own modules and lightweight data/schema dependencies. `wia.contracts` and environment/policy protocols use the Python standard library only. Importing WIA, CLI help, task listing, backend metadata or preparing a dry run never imports ShowHarness, its internal `core`, GUMI, MCP or a model. Selecting `show_harness` at execution time lazily imports `showharness.evaluation`. Standalone Harness retains no mandatory WIA dependency; its migrated benchmark compatibility modules need the optional WIA package/source bridge.

The trial orchestrator resolves task defaults and explicit overrides, computes task fingerprints and checks a fresh output destination. It freezes `effective_config.json`, creates one executor for each selected episode and reads the executor's authoritative summary. The active adapter invokes `scripts.run_esi_explore_episode.main` for launch or `scripts.run_esi_agent.main` for attach. The former retains persistent native process launch, GPU selection, scene initialization and gateway ownership; the latter attaches to an already prepared scene and does not reset it. Harness alone counts decisions, model calls, macro/primitive actions and physical steps. WIA preserves these counts and the underlying summary; it does not invoke `PolicySystem.decide` around the Harness loop.

`PublicEpisode` and `PublicObservation` carry only evaluator-approved task instructions, sensor data and action feedback. `PrivateEvaluationContext` contains evaluator references and is intentionally absent from every `PolicySystem` method. Private state, task answers and evaluation traces must never enter public payloads. Immutable configuration equality is enforced again by the existing Harness loader/manifest checks at execution. WIA rejects changed task bytes between preparation and dispatch.

`PolicySystem` describes lifecycle and capability metadata for future systems. A whole-trial executor can adapt such a policy to an environment without changing the CLI, registering through the local registry or the `wia.policy_systems` package entry-point group. This accommodates WorldModel, WAM and Claude research systems as documented interfaces only. No dummy policy or simulated success path is shipped.

Backend identity is separate from action capabilities. Canonical names are `codex_cli`, `openai_chat_completions`, `openai_responses` and legacy `local_http`. Harness's `codex` alias still selects the original Codex episode session. Existing native/local immutable session values remain `native_persistent` and `local_http_persistent`. New API session IDs are `openai_chat_completions_persistent` and `openai_responses_persistent`, with explicit backend metadata. Codex owns native conversation history; both explicit API sessions and legacy local HTTP keep history in Harness. Native interruption resume and diagnostic history interventions remain Codex-only.

Scientific settings are inherited from each task unless explicitly overridden. Attach inherits prepared manifest settings and rejects conflicting task/model/backend/episode selections. Error status and scoring validity are separate: completed unsuccessful physical behavior counts as an agent failure only with a complete valid evaluator result; interrupted/model/environment/runtime failures and unavailable scoring remain separate categories. Runtime timing and model usage are preserved, while unavailable monetary cost remains null.

Editable installs are the supported resource workflow for this migration. Full task trees, YAML/JSON scene sources, Markdown prompts and native scripts remain in their checkouts. A stripped wheel is not an execution artifact; resource checks give an explicit reinstall/configuration instruction. The simulator environment and any separately licensed native assets are required to launch physics. Base evaluation preparation and CPU-only protocol/integration tests need neither.
