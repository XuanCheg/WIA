# WIA v0.2 输入、提示词、工具、上下文与评分核对

Current implementation update: shared HTTP context policies now apply across transports, and perception schemas remain visible at the cap with local enforcement. See [formal evaluation readiness](/local_home2/zhouxinyang/models/WIA/docs/FORMAL_EVALUATION_READINESS_20261031.md) for current behavior and a complete archived episode. The following protocol review retains its earlier snapshot.

这份文档说明 2026-10-31 工作区的实际实现，供人工检查。主集现有 60 个任务别名：原 59 个任务加 T52「物体初始已在容器内」。T15–T17 的任务和场景定义保持不变。扩展集、暂时移除的 D 系列和未选变体不计入主集。

先明确三点：`DONE` 只结束尝试，成功由私有评分器判断；可达性检查和截图不等于完成任务；当前评测入口没有实现跨任务加权总分。本文后面的建议汇总公式还没有写入评分器。

本文是实现审计，不是模型成绩报告。私有答案、物体世界坐标、评分参数和下列 `task_contracts.json` 都不能进入普通 benchmark 的模型输入。用户此前授权的全信息抓取调试属于另一种诊断条件。

## 1. 一次评测的输入与输出

| 层次 | 输入 | 输出与用途 |
| --- | --- | --- |
| 数据集 | 别名、任务 YAML、场景 YAML、选定 variant、seed、原始来源和外部资产 | 公开目标、初始化场景、私有评分配置。R-A1/R-A2 共用旧 task ID，必须用别名和定义哈希区分 |
| 实验配置 | 模型、backend、生成参数、动作模式、步数、世界时钟、观测条件、历史策略 | `effective_config.json` 固化每次实验条件；配置可覆盖默认值，因此不能只看任务名比较成绩 |
| 模型决策 | 公开任务、授权 RGB/深度、本体状态、上一步执行反馈、可用动作及边界、剩余预算 | 一个动作命令；默认还要求 `world_observation`。特定问答任务增加公开答案字段 |
| 控制器 | 已通过 schema、能力和幅度校验的单个动作 | 执行回执、实际位移/姿态、停止或失败原因，以及新的观测；回执完成不等于抓住物体 |
| 私有评分器 | 原生物体关系、接触、速度、抓取约束、仿真时钟、任务事件和已交付视觉证据 | `completion_items`、有效性、约束、`task_success` 及任务专属证据；不把私有真值回灌模型 |
| 评测汇总 | 每次 episode 的最终 summary | `results.json` 内逐次结果、状态计数、token 用量和费用；当前没有统一 accuracy/macro score 字段 |

公开任务只允许 `task_id`、`task_version`、`objective`、`success_criteria`、`environment`、`constraints`。episode 配置公开步数、时钟模式、观测条件和动作模式等必要规则。默认值逐任务列在附录，不存在一个覆盖所有任务的固定步数。

正常首轮附带冻结的初始全局概览和 8 路机载 RGB。后续默认附带头部、左右手腕、后底盘 4 路；另 4 路底盘 RGB 由工具读取。8 路仍被采集，减少默认附件不代表摄像头不存在。初始全局概览不会在后续刷新成实时上帝视角。原始 RGB 默认不缩放；显式的 `image_max_edge` 是另一项实验设置。

机器人本体状态包括关节、手臂正运动学、抓手状态和里程计。普通底盘位置使用 `odometry_local`，不等于私有仿真世界坐标。末端与动作使用机器人基座坐标：+X 前、+Y 左、+Z 上。相机光学坐标为 +X 右、+Y 下、+Z 前。深度是以米为单位的光学 Z，不是到相机中心的欧氏距离；像素 `[u,v]` 从左上角计数。相机位置也不等于抓取中心。

输出示例，具体以该步 `response_schema` 为准：

```json
{"command":{"action":"MV_UP","distance_m":0.02},"world_observation":"The gripper is below the object."}
```

```json
{"command":{"action":"DONE"},"world_observation":"The object appears stable inside the container."}
```

`world_observation` 是模型公开描述，写入日志，不是裁判依据，也不是自动可信记忆。启用问答协议时，答案、置信度和简短证据说明按任务 schema 增加；不是所有任务都接受统一 `answer` 字段。关闭观察日志后的 fixed 输出是 `{"action":"..."}`；parameterized 输出仍有 `command` 包装。

人工复查一次 episode 时，先看 `run.json` / `summary.json` 的生效条件、终止原因和最终评分，再看 `steps.jsonl` 中逐次决策、请求尝试与执行回执。`model_inputs.jsonl` / `model_outputs.jsonl` 记录实际模型交互；逐步目录内的 `model_inputs.json`、`snapshot_artifacts.json`、`before/observation.json` 和 `raw_depth_input.json` 可核对图像来源、公开状态及深度访问范围。私有评分证据单独保存在 native evaluation 输出中。

## 2. 全局提示词如何组成

入口是 [main.md](/local_home2/zhouxinyang/models/WIA/explore_to_achieve/prompts/main.md)，由 [prompts.py](/local_home2/zhouxinyang/models/WIA/src/wia/runtime/agent/prompts.py) 按白名单组装，记录组件哈希。完整原文保存在 [提示词附录](/local_home2/zhouxinyang/models/WIA/docs/releases/v0.2/protocol_review/PROMPT_TEMPLATES.zh-CN.md)。

| 部分 | 实际内容 |
| --- | --- |
| resident | 机器人执行者身份、感知规则、R1 机器人说明、动作接口与动态能力、感知工具、操作和反馈解释、保护规则、完成规则、可选 world observation 插件 |
| episode_start | 首轮规则、公开任务与环境、episode 配置、初始图像与本体状态、严格输出 schema |
| decision_step | 本轮图像与本体状态、上一步执行反馈、当前能力、剩余预算、观测来源与时间、输出 schema |
| 条件组件 | 问答完成规则、历史笔记、历史 RGB、工具预算；全信息可达性插件只在显式诊断模式启用 |

操作提示要求依据实际反馈修正动作，区别请求幅度、量化后的幅度和实际完成幅度；不确定是否已经执行时不能自动重放。允许在任务约束允许时改换目标，但不能跳过明确的顺序或历史要求。保护规则要求避免强行碰撞；没有统一“所有家具禁止移动”的规则。T22/T46 的可移动椅子按用户审阅结论接受，任务明确保护的装置仍按各任务约束处理。

完成提示不会把“说完成了”当成功。一般物理任务由最终测量判定；需要显式提交的机制任务在 `DONE` 时结算。问答模式有不同终止规则：纯 QA 可以在达到答案置信度阈值时提前结束；answer-and-place 中答对只完成问答部分，仍须完成真实放置。不能把这几种模式混成一种协议。

## 3. 工具与动作设计

模型感知工具与控制器的机器人接口分开。模型通常提交 JSON 动作，由 runner 校验后调用控制器；并没有把全部模拟器 API 作为模型工具公开。

| 接口 | 参数/限制 | 返回及权限 |
| --- | --- | --- |
| `read_depth_pixels` | `sensor` 仅 `head_depth_m` / `wrist_depth_m`；1–256 个原生 `[u,v]` | 原始 float32 光学 Z；无效值为 null；没有检测框、物体身份或目标判断 |
| `read_depth_region` | 原生坐标矩形，最多 1024 像素 | 每个像素的深度矩阵，不做平均或缩放 |
| `read_rgb_camera` | 前左、前右、左、右底盘相机之一 | 当前已授权快照的一张 RGB；不会推进世界或重新拍实时画面 |
| `episode_note` | 特定 Vercel 历史策略；append/read；每次决策累计最多写 128 字符 | 模型自写笔记，没有真值校正；不是每次 API 调用重新获得 128 字符 |
| `read_historical_rgb` | 显式支持的 Vercel 历史模式；过去 decision_step + camera | 只能取曾实际交付的历史图像，每次决策最多 4 次；不能补看从未交付的私有视角 |
| `submit_decision` | 显式启用的 typed function 输出路线 | 提交单个合法决策；常规路线仍可使用严格 JSON 输出 |

fixed 模式每次只选一个动作，幅度由实际 primitive 配置给出；parameterized 模式平移用正数 `distance_m`，转动用正数 `angle_deg`，方向包含在动作名。幅度必须符合该步动态边界；按 primitive 分辨率做 nearest-half-up 量化，量化为零的请求被拒绝。一个命令可以内部执行多步，但只有一个 Agent 动作边界，中间没有新的模型观测。

动作覆盖底盘前后左右平移和转向、工作末端三轴平移、可用时的躯干升降和腕部转动、`GRASP`、`RELEASE`、`DONE`。启用右手能力时另有 `RIGHT_*` 命令；每次决策控制一只手。`GRASP/RELEASE/DONE` 不带幅度字段。抓手闭合比例不是抓取成功置信度；真实 holding/约束状态由原生测量确认。

当前 recent-notes 路线默认每次决策最多 4 轮感知工具调用，到上限后移除感知工具并要求动作；笔记读取不按感知轮数计费。这个上限及是否提供历史工具属于 backend/历史策略设置，不是所有模型共有的固定接口。

通用 runner 的 `max_invalid_retries` 默认是 2，但当前 Vercel session 显式使用 `consume_step_and_feedback`：非法决策消耗一个决策步、不执行机器人动作，错误反馈给下一步，不在同一步套用上述重试数。两阶段任务的第一阶段也有预算计次规则。动作失败、非法输出与 API 错误分别记录；比较实验必须记录这项 backend 差异。

## 4. 上下文、历史与时钟

| 策略 | 当前实现与比较时应记录的差异 |
| --- | --- |
| 默认/full | 由选定 backend 的原生会话或 Harness 管理历史；不能把不同 backend 默认历史当成完全相同 |
| `current_sensors_full_text` | Vercel 专用路线；保留历史文本，去掉旧图像，提供当前传感器 |
| `current_sensors_recent2_notes` / `current_sensors_last_result_notes` | 两者是同一实现别名；实际只带上一次公开执行结果、当前传感器和可读写笔记，不是两轮完整多模态历史 |
| `showharness_state` | Vercel 的状态投影与近期动作；近期动作数由配置决定 |
| `recent_text` | 显式诊断配置按历史文本轮数裁剪 |
| `sliding_window` | 显式 vLLM 诊断路线，根据配置窗口裁剪，预留输出预算 |
| TM 的 `history_removed` / `history_oracle` | 另一套两阶段诊断干预，在第二阶段改变历史输入；oracle 事实由调用者提供，不能与标准成绩混报 |

老的 `memory_mode=model_notes` 参数不能据其名称认定可用：当前 native prompt assembler 拒绝非 `none`，而 `episode_note` 属于上表显式历史策略。初始视图冻结实验 `initial_view_only` 也不是当前观测实验，必须单独记录。

普通任务是否在模型推理时推进世界取决于任务 defaults 和实验覆盖。M4 按用户确认采用仿真秒：正确、独占占位才累计加工时间，搬运消耗同一仿真时钟，等待模型/API 时暂停世界。中断占位会重置尚未完成的加工段。不能把等待 API 的墙钟时间算成加工时间。

部分 backend 使用输入预算估算，例如 DeepSeek 路线用 UTF-8 字节数和图像 patch 估算，再预留输出与安全余量。这是保护性估算，不是所有模型统一的 tokenizer 计数。报告需要保留实际模型、API/backend、输出上限、reasoning 设置、历史策略、图像设置和用量。

| R-C1–R-C3 | 根据镜中对应选原物体送达，最终版按配置的选择/稳定放置项计分；保护非目标，不再要求通用 5 cm 抬升 |

| R-A1、R-A2 | 外观模式报告和物理送达；采用最后一次合法最终报告，同时判定真实目标与稳定放置。共享旧 ID 不意味着可以合并计分 |
| GF2-1、GF2-2 | 纸盒穿开口、砧板入槽；两项为采样证据支持的真实穿越、稳定放置，`DONE` 时最终选件结算。穿越必须发生，取消抬升门槛不等于允许直接在目标位置出现；采样轨迹不声称连续路径证明 |
| GF3-1、GF3-2 | 黄瓜按长度、香料罐按高度匹配；两项为正确分配、全部稳定放置。比较物体本征尺寸，不把朝向变化造成的世界 AABB 变化当真实尺寸变化 |
| H1（`iw_h1_02`） | 翻转刚性包装并在送达前实际看到验收标记；缺陷分支须隔离原件、送兼容备用件，合格分支保留备用件。不是切割或食品变质物理 |
| H2（`iw_h2_02`） | 移开阻碍并送达，随后经历脚本声明的检查/扰动事件；必须观察事件后工作区并满足最终清空与存放。仅第一次送达不足以通过 |
| H3（`iw_h3_03`） | 根据实际外部移除事件维持最低库存；保留原有库存，只允许填补当时缺口，额外无必要补货会失败 |
| H4（`iw_h4_02`） | 目标稳定放置，移动过的障碍存入指定区域，锚点保持；核对原生手臂接触和最终退出。搬移数量记录为成本，不自动加权扣总分 |
| H5（`iw_h5_02`） | 观察目的地状态后释放；优先位可用则用优先位，否则备用位；保护原住物和其他指定对象 |
| M1（`iw_m1_01`） | 真实清洁接触事件、机器人收到使用事件观测、身份连续性；使用过与未使用工具分别稳定分流。这里的资格是事件状态，不推断液体污染 |
| M2（`iw_m2_01`） | 不可拆分库存件按数量分配，逐件唯一归属，各订单总数必须精确满足，剩余归库存；可行分配由枚举验证 |
| M3（`iw_m3_01`） | 实际查看内部内容后选择合资格柜体；原住物位置与原生 Inside、目标唯一归属/稳定 Inside、关闭要求（如配置启用）共同核对 |
| M4（`iw_m4_02`） | 处理站独占、一次只持一物、每件加工完成、真实装载/交付搬运、最终工位清空、仿真 deadline 全部满足；枚举调度是可行性参照，不替代真实时间证据 |

H1–H5/M1–M4 返回必需 `checks` 与三值证据：True、False、None。所有证据齐全且所有必需条件为 True 才成功；缺证据不会伪造为失败零分。它们目前没有把内部每个 check 暴露成独立完成分项：通用包装将其作为一个整体目标，因此是 0/1 完成分。动作成本只做诊断，H3 明确禁止的多余补货则是成功条件本身。

静态可达性使用三维手臂工作空间、关节限位、可升降躯干、候选底盘站位和碰撞近似筛选。它是有界的几何证据：没有找到见证不代表不可抓，找到见证也不保证夹爪接触、摩擦、搬运和插入都能完成。可移动椅子不能简单作为永久封闭障碍。T22/T46 及四个 GF 场景的旧 concern 已按用户审阅关闭，不再安排额外验证；历史报告保留以解释当时结论。

## 6. 单任务分数、成功和有效性

通用归一化在 [completion.py](/local_home2/zhouxinyang/models/WIA/src/wia/tasks/completion.py)。设该任务声明了 N 个完成项，有效且完成的数量为 C：

- 证据完整时，`completion_score = C / N`，一般 `score_percent = 100 × C / N`。
- 任一完成项缺失/不可测，保持原分母，官方完成分为 null；另报 `diagnostic_lower_bound = C / N`，不能将下界冒充正式得分。
- `task_success` 还取决于该评分器的全部约束与终态。因此完成分 1 不必然等于成功；事实进度可以在后续约束失败后保留。
- 测量错误、中断、初始化失败与真实完整失败必须区分。`model_error`、`runtime_error`、`environment_error`、`execution_error`、`observation_error`、`cancelled` 均保留各自状态；中断时最终质量分置 null。

**T05/T06 有一个需要单独审阅的例外。** 组合任务先算物理/语义义务完成比例，并将它保存在 `obligation_score_percent`；对含 answer sheet 的组合任务，最外层 `score_percent` 改为唯一语义问题的等权正确率 `100 × correct_answers / required_unique_questions`。`completion_score` 仍是义务进度。完整成功同时需要全部物理义务、全部问题正确、约束成立且无答案格式错误。不能假设所有任务的 `score_percent` 都等于 `100 × completion_score`。

安全分、安全暴露、任务约束和目标完成属于不同字段。通用归一化没有一个隐含的统一碰撞惩罚系数；哪些接触使任务失败由实际任务评分器决定。不要从全局提示词自行推导一条不存在的计分规则。

## 7. 数据集总分：已有实现与建议

[evaluation/runner.py](/local_home2/zhouxinyang/models/WIA/src/wia/evaluation/runner.py) 当前输出逐次 trial、各状态数量、token 汇总，以及所有 trial 费用都已知时的费用之和。它没有计算任务均分、六类均分或子类均分。本文不新增评分权重。

如需发布总分，建议先确定以下报告口径：

1. 主指标用完整任务成功率，另报完成进度。这样不把 T05/T06 的答案正确率与其他任务的物理进度直接混加。
2. 明确固定评测集合、每任务 seed 数及基础设施错误处理。报告已完成有效次数/计划次数，列出全部无效和中断原因；不能静默删掉难任务或失败运行。
3. 对有效运行 V，诊断成功率可写为 `100 × Σ success / |V|`，同时给覆盖率 `|V| / N_planned`。若采用固定计划分母，则必须预先约定基础设施错误重跑及未完成处理，不能在出分后选择分母。
4. 对各任务先在相同 seed 计划下聚合，再分别报告任务等权均值和“子类内任务等权 → 类内子类等权 → 六类等权”的 macro。空子类不能暗中补零或忽略，应显式标为无覆盖。多 seed 不应让某任务重复获得更大权重。

建议 macro 公式为 `100/6 × Σ_family mean_subclass(mean_task(success_rate_task))`。这只是报告建议；当前没有已算出的 WIA 总分，也没有本轮模型成绩。

每次成绩旁建议同时列出执行动作数、模型调用数、墙钟耗时、仿真耗时、推理/工具/控制延迟、token 和费用。使用历史删减、oracle、全信息坐标或直接状态设置的结果分别标注诊断条件。

## 8. 本轮验证如何解释

T42–T44 使用模拟器直接放置/释放，每种候选物体重复 3 次，保持原 3 秒窗口及 0.15 秒并列阈值。实验设置了物体位姿和初始速度，所以只能证明该条件下的被动物理结果；不能据此将 `robot_trial_valid` 或 `task_success` 改成 True，也不能推断机器人能完成全流程。
