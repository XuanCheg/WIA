# Scene-based redesign of InteractiveWorld candidates

## Design policy

Start from a scientific question and a suitable InteractiveWorld scene. Preserve useful context, objects and causal structure, then change the scene and task contract to make the question measurable through robot action. Existing WIA taxonomy is an overlap baseline, not a required destination for new designs. Decide classification and release placement after task definitions are sound. Integration into V1 or a later release remains undecided.

Knowledge-guided real pick-and-place is admissible. Priority depends on whether knowledge affects physical feasibility, action selection, progress tracking or feedback-driven revision. Generic transport after a solved semantic question remains a lower-priority diagnostic. No particular existing implementation family is prescribed.

All changes below are proposals. This review changes documents only; neither source scenes nor existing WIA tasks have been edited. Shared BEHAVIOR assets make reuse plausible, but robot reach, controls, cues, state effects and evaluation still need adaptation.

## First design package

Develop P1–P5 first as scene specifications, not as immediate executable additions. Their priority comes from distinct decision dependencies, not a taxonomy vacancy. P1/P5 may eventually share a family; P2 must demonstrate more than the existing two-phase change-and-restore tasks; P3 must measure current completion rather than merely recall a list; P4 must require state-dependent clearance rather than a fixed cleanup script.

Keep the original scene when it supports the scientific question. Change work heights, access paths, object poses or assets only when needed for robot execution or controlled counterfactuals. Record each change and its scientific effect. A rigid replacement for a spill or deformable item preserves some decision structure but changes the physical phenomenon and must be labelled as a redesign.

## Common robot conversion contract

1. Replace the human executor with robot-owned observations and actions. Remove human intention cues, speech matching and intervention timing unless an explicit interaction research question requires them.
2. Preserve useful history through actual robot sensor observations. Hide evaluator identities and answer-bearing internal object keys.
3. Define the high-level goal, necessary knowledge, decision alternatives and physical outcome before choosing a controller or category.
4. Score physical relations and meaningful process constraints. Accept all valid plans; do not copy reference command sequences as the only solution.
5. Pair variants where evidence changes the correct decision. Keep unrelated observation and execution conditions matched, and include no-change/no-repair branches when appropriate.
6. Separate source-supported behavior, proposed scene changes and unvalidated feasibility. Declared state changes or visual effects cannot support stronger material-dynamics claims.
7. Compare with current WIA tasks to establish incremental scientific value. Assign categories only after this comparison; creating a new category is neither a prerequisite nor a success criterion.
