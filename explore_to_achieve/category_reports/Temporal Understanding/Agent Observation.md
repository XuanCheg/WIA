## Final implementation and scientific boundary

Converter version: **1.0.1**. Decision: **publish all pending candidates and all diagnostic failures for Review**. This decision does not certify native loading, robot execution or physical qualification. Shared publication is owned by the main runner; this agent did not launch workers or manually enqueue captures.

The converter implements `inspect`, `convert`, deterministic `convert_all`, stratified `sample`, an owned initialization hook, and the `category_operation` qualification/evaluator adapters. Generated scenes use `original_scene`; physical tasks use `physical_task`. All original variants remain empty. No source file, asset, object scale, prop pose, shared module, approved record or root research log was edited.

The operation is `observe_objects_and_return`: approach every original task-category prop within the source proximity threshold (1 m in this corpus), depart at least 0.5 m from the measured episode start, travel at least 0.8 m horizontally, return within 0.15 m, and remain stopped for 15 consecutive control samples. A visit requires three consecutive native proximity samples after at least 0.1 m of genuine travel. Native object centres and actual R1 positions determine visits. Original answer/count/path/visibility flags do not participate in success. Visual recognition is auxiliary; a proximity visit alone does not prove recognition.

Qualification reads the actual R1 pose/heading, uprightness, native floor contacts, absence of external nonfloor robot contacts, exact original bindings, prop collidability, support and stability, and agreement with saved source positions. Evaluation additionally checks translation/rotation continuity against the existing controller bounds, unobserved pose changes, full-episode contact/support safety, prop position preservation within 3 cm, departure, visits, return and stopped stability. Native velocity and consecutive pose differences must both indicate stopping. All actions remain on the existing guarded robot controls. Qualification and evaluator hooks contain no native setters, simulation steps or executor actions.

The only L2 scene change restores the existing R1 to `/start_xy`, `/robot_start_z` and `/step_log/0/robot_quat_xyzw`, after source postprocessing overwrites the construction pose with the final endpoint. The initialization hook validates the source checksum/provenance, runs once before controller construction, and flushes stale endpoint contacts with the original 30-step settling convention. It changes no reference camera or prop and installs no runtime replay callback. This category already has R1, so `add_existing_r1` is unnecessary. Navigation retains original prop physics; there are no manipulation targets requiring `object_physics`. The installed `HolonomicBaseRobot` uses `fixed_base=True` for its articulated base, so qualification deliberately does not reject that legitimate setting.
