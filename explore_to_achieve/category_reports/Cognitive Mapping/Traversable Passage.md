## Retained implementation: 1.0.1

The owned [converter](/local_home2/zhouxinyang/models/Show-Harness-Explore/core/esi_converters/cognitive_mapping_traversable_passage.py) implements `inspect`, `convert` and deterministic `convert_all` through the shared batcher. It supplies the owned `qualify_operation` and `create_evaluator` hooks. Invalid endpoint/reference contracts return explicit `not_convertible_under_L1_L2` diagnostics through the same complete batch protocol. The current 60 valid sources need no such exclusion.

Two recipes are selected deterministically from source identity and seed, independently of answers: `passage_arrival` and `passage_round_trip`. An explicit `traversable_passage_operation` configuration selects either recipe category-wide. Public instructions disclose only the publicly named endpoints, operation and constraints. They do not reveal source answers, intermediate rooms, camera poses, paths, maps or scorer state. Original QA is preserved verbatim in each candidate's `private_qa.json`. Physical arrival does not establish shortest-path optimality or the original MCQ answer.

Every adapted scene declares exactly one initialization-only `robot_pose` patch. Its XY and heading derive from the original initial camera's position and look target; root Z is the installed floor-0 convention plus 0.1 m clearance, explicitly unqualified. Additional head pitch is zero. The original empty-patch variant remains available. No asset, door, lamp, object pose, physics flag, scale, source camera, source data or shared code was changed. The builder already includes installed R1 and original doors, so `add_existing_r1`, mechanism-restoration hooks and manipulation-object physics patches are unnecessary here.

Native qualification reads the actual R1 and its holonomic base controller, endpoint labels, exact initial XY/heading tolerances, upright chassis, entire nine-point chassis AABB occupancy and original floor contacts. The original floor layer must match within 0.005 m; nonfloor contacts reject qualification. A fixed articulation root is allowed because the installed R1 moves its physical `base_link` with holonomic joints.

Physical terminal success requires all of the following, independently of QA:

- A natively qualified source start and measured ordered visits to the destination, followed by the source for a return recipe.
- At least 0.25 m of measured real travel and a positive number of low-level controller samples.
- Increasing native simulation time and displacement within the existing controller's speed/time/tolerance bound at every sampled step. Unobserved endpoint motion is rejected.
- Maintained original-floor support, upright pose and no external nonfloor contact. A sampled violation invalidates that episode.
- Three consecutive settled controller samples fully inside each requested destination and three current terminal samples. Terminal chassis linear/angular speeds are at most 0.02 m/s and 0.1 rad/s.

All robot actions remain in existing guarded controls. Qualification/evaluation hooks do not move robots, objects or cameras, run source effects, step the simulation, or consult source success flags. Private `state.json`, action-level evidence and low-level trajectory records contain measured state and travel; none is an Agent input.
